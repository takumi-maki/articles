# タイトル
識別子をstringで持つのをやめた話

## 概要
TypeScript を使っていても、識別子をすべて string で扱うと、引数の取り違えはコンパイル時に検出できません。本セッションでは、識別子を Value Object として定義し、型の粒度を上げることで事故を防いだ実践例を紹介します。

## 問題
UserId・ProductId・OrderId を同じ string 型で扱っており、引数の順番を誤ってもコンパイルが通る状態でした。型があるにもかかわらず、本番で不整合が発生しました。

## 気づき・判断
APIの境界では string を受け取り、ドメイン内部では専用型に変換する設計に移行しました。識別子ごとに型を分けるという判断でした。

## 聴講者への学び
識別子を string のまま扱うリスクと、型の粒度を上げる設計判断を実装ベースで共有します。

## 聴講者への学び
型の粒度を上げることで得られる安全性と、その実装判断を共有します。

フロントエンド／バックエンド／フルスタックエンジニア
