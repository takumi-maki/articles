# タイトル
識別子をstringで持つのをやめた話

## 概要
TypeScript を使っていても、識別子をすべて string で扱っていると、引数の取り違えはコンパイル時に検出できません。本セッションでは、識別子を Value Object として定義し、型の粒度を上げることで事故を防いだ実践例を紹介します。

## 背景
UserId・ProductId・OrderId などを同じ string 型で扱っており、識別子同士を区別できない状態でした。

## 問題
引数の順番を誤ってもコンパイルは通り、本番で不整合が発生しました。型があるのに安全ではありませんでした。

## 気づき・判断
識別子ごとに専用型を定義し、Value Object として表現する設計に移行しました。

## 聴講者への学び
型の粒度を上げることで得られる安全性と、その実装判断を共有します。

## 対象となるロール
フロントエンド／バックエンド／フルスタックエンジニア
