# タイトル
GraphQLスキーマ駆動で型の二重管理をやめた話

## 概要
フロントとバックで型を二重管理していた状態から、GraphQL スキーマを単一の型定義源とする設計に移行しました。型を共有するのではなく、型定義の起点を一つに定めるという判断です。

## 背景
API 型と UI 型をそれぞれ定義していたことで、不整合や変更漏れが発生していました。

## 問題
手動で型を同期させる運用では、フィールド追加時の反映漏れや nullable の扱いの不一致が頻発していました。

## 気づき・判断
GraphQL スキーマを唯一の型定義源とし、生成された型を各レイヤーで参照する構成にしました。

## 聴講者への学び
型を共通化するのではなく、型定義の起点を明確にする設計パターンとその実装例を共有します。

### 対象となるロール
フロントエンド／フルスタックエンジニア

### 想定レベル
初級〜中級
TypeScriptを業務で利用しており、GraphQLの基本概念を理解している方
